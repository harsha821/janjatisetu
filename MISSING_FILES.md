# Status: complete

## Coverage Gap feature (latest pass)

Reported: the Coverage Gap feature had no way to fix gaps. Confirmed and fixed:

- **No way to fix a gap.** Added `POST /admin/coverage-gap/{id}/resolve` (`DISMISS` with a mandatory reason,
  `MARK_APPLIED`, `REOPEN`) and matching actions on each record in the Flutter Coverage screen.
- **Outreach claimed success when nothing was delivered** (unregistered student, no mobile number, SMS disabled).
  It now returns `delivered` / `queued` / `undelivered`, records that on the `Outreach` row, and the gap explains why.
- **Re-running detection duplicated "uncertain match" review cases** every time, despite being documented as safe to
  repeat. It now skips records that already have a case (including ones a reviewer resolved).
- **Funnel "Outreach sent" over-counted** (it included gaps auto-closed with no outreach). It now counts gaps
  actually contacted; added `ready_for_outreach`.
- **Flutter screen:** added state filter chips, "Load more" pagination (was capped at 100), a top-districts card
  (the API returned this but the screen ignored it), and `mounted` checks after `await`.
- Added tests: `test_coverage_gap_can_be_fixed_by_a_reviewer`,
  `test_rerunning_gap_detection_does_not_duplicate_review_cases`. Updated `docs/API_REFERENCE.md` and the README.

**Not run:** no packages / Flutter SDK were available here, so the new backend and Flutter code has been syntax-checked
only. Run `pytest` in `backend/` and `flutter analyze && flutter test` in `mobile/` before relying on it.
